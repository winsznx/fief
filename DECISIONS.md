# Decisions

Chronological log of load-bearing decisions. Newest first.

## 2026-08-25

- **PRD v2 supersedes v1** (`internal/fief-prd-v2.md`), absorbing the `internal/patch.md` review in full. v1 kept for history.
- **Forward epochs + slot completeness adopted.** v1 let the runtime discard a decision before consuming a nonce (v1 §10) with no on-chain freshness requirement, which let an owner run N inferences and publish only the winners. v2 fixes the slot schedule on-chain before any outcome is knowable, enforces a per-slot commit deadline, and resolves every scheduled slot to Committed / Missed / Invalid. Chosen over merely rewording the README claim: fix the mechanism, not the sentence.
- **Commit/reveal lifecycle adopted.** v1 published `respData` in calldata at decision time, which gave the signal away for free and made renting pointless. v2 commits a sealed receipt before the deadline, delivers cleartext to renters immediately, and reveals publicly after the market horizon. This is the economic core, not a privacy nicety.
- **The `eip-7857-draft` fork is dropped.** Its verifier is a no-op on both paths, its `authorizeUsage` lacks permissions, and its interface is GPL-3.0. `FiefAgent` becomes ~150 lines of our own MIT code, so the contracts package is uniformly MIT with no vendored GPL.
- **Identity/record network split.** The Agentic ID SDK (`@0gfoundation/0g-agenticid-sdk@0.1.2`) states in `constants.d.ts` that **no mainnet deployment exists**. Wave 3 requires a mainnet contract, so Fief's own contracts go to mainnet 16661 while Agentic ID (ERC-7857) and the ERC-8004 ReputationRegistry run on testnet 16602, labelled testnet in all copy. This corrects patch.md, which assumed those registries were live on mainnet.
- **Storage SDK swapped** to `@0gfoundation/0g-storage-ts-sdk@1.2.11` (maintained) from the deprecated `@0glabs/0g-ts-sdk@0.3.3`. Gate P0.4 is deleted rather than run: there is nothing worth proving about a dead package.
- **P0.1 funding gate closed, not relaxed.** Operator wallet `0xbF7EF9…Bf31` already holds a mainnet Compute ledger (9.4545 OG total, 0.1 available) from prior use; `MIN_ACCOUNT_BALANCE()` is 3 OG and is already cleared. P0.2 is runnable immediately. Testnet is at 0 OG and needs a faucet top-up before P0.5.
- **Rental moved into Wave 3 (P4.5).** The pre-committed demo video shows a second-wallet rental, and shipping a video that contradicts the code is not an option. Deadline risk was raised and accepted by the owner; §16.1 records the fallback order.
- **Frontend migrated to the v2 data contract.** `web/` now speaks `slot:` rather than `nonce:`, `DecisionEntry` carries a `SlotState`, and `decision` is optional so a committed-but-unrevealed slot renders "sealed until reveal" instead of a blank. `EpochSummary` is derived from each ledger, never authored, so the completeness bar cannot disagree with the rows beneath it. `RejectReason` narrowed to the five reveal-time failures a viewer can actually see.
- **The frontend imports the reference model, so this drift cannot recur.** `@fief/reference` is a devDependency of `web/` and `commit.parity.test.ts` asserts byte-equality of the commit line, including that `nonce:` never returns. It stays out of the browser bundle; only the test touches it. Two parallel implementations is what let v1 and v2 diverge silently in the first place.
- **0G Storage integrated; the sealed strategy is really sealed.** The strategy container is encrypted AES-256-GCM app-side (Fief holds the key, not the SDK) and the ciphertext is uploaded through `@0gfoundation/0g-storage-ts-sdk`. The merkle root is computed locally from the same bytes and compared against the indexer's, so a mismatch fails loudly rather than registering a root that does not describe the blob. Mainnet upload tx `0x8140d9b2…`, `storageRoot` `0xaf4d2e5c…`. That makes four 0G components load-bearing: Chain, Compute, Storage, and Agentic ID on testnet.
- **The red transaction succeeds on purpose.** `revealDecisionStrict` catches the revert and emits `DecisionRejected`, so the demo's tamper shows on ChainScan as a successful transaction carrying `DecisionRejected(agent 5, slot 1, "BadReveal")`. A reverted transaction reads like the system broke, when what actually happened is the system worked. The honest reveal of that same slot lands afterwards and takes the epoch to 100% completeness, which is the anti-griefing property demonstrated rather than asserted.
- **P4 core complete: Fief is live on 0G mainnet 16661.** RecordBook `0x40eB003340f467e096F8Ae30f8696bE40Eba922c`. A real forward epoch ran 2/2 committed, 2/2 revealed, 100% completeness, and the adversarial suite is 4/4 on mainnet. Addresses and tx hashes in PRD v2 §16 P4. Deployment cost about 0.033 OG; 0.942 OG remains.
- **On mainnet the TEE signer resolves live, so the strong claim holds.** `pinnedSigner` is the zero address and `expectedTeeSigner` returns `0xA46EA4FC…46B9` directly from `InferenceServing.getService`. The testnet rehearsal needed the `pinSigner` escape hatch because a testnet RecordBook cannot resolve a mainnet provider; that caveat does not apply to the mainnet deployment and the §2 wording stands unnarrowed.
- **Slither audit before mainnet, one real bug found.** `RentalDesk` pushed ETH with `call{value:}`, so an agent owner that reverts on receive could permanently block settlement and freeze an honest renter's escrow. It also silently contradicted the PRD's own "pull pattern, no push transfers". Replaced with credited balances plus `withdraw()`, which zeroes before sending. Reading the code alongside the report also turned up `settledCount` never being incremented, which made the allowance bind only within a single call and made the field always read zero. Full triage, including why the two remaining findings are false positives, in `contracts/SLITHER.md`.
- **Deploy 0G with `--legacy --with-gas-price 4000000000`.** Beyond the bogus estimate noted below, the node also rejects EIP-1559 transactions whose tip cap it computes as 1 wei. Legacy pricing with an explicit gas price is the only reliable combination found.
- **P3 complete: the full loop runs on live 0G.** `runtime/` drives a real forward epoch on testnet 16602 using real TEE-signed inference from mainnet Compute: 2/2 slots committed inside their deadlines, 2/2 revealed and verified byte-exact on-chain, completeness 100% read back from `EpochBook`. The adversarial CLI is 4/4: late commit, early reveal and a one-byte tamper all rejected, and the honest reveal of the tampered slot still accepted. Addresses and tx hashes in PRD v2 §16 P3.
- **`openEpoch` takes the provider set; a separate `pinProviders` call raced `startTime`.** The pin must land before the epoch starts, and splitting it across two transactions meant the second could simply arrive too late on a live network, leaving an epoch nobody could ever commit to. It failed exactly that way on the first testnet run. Providers are now pinned in the same transaction; `pinProviders` survives only for topping up before start.
- **Compute on mainnet, contracts on testnet, for P3 only.** The funded Compute ledger lives on mainnet and creating a testnet one costs a 3 OG minimum we do not have there. The consequence is that the testnet `RecordBook` cannot resolve a mainnet provider through its local `InferenceServing`, so the TEE signer is pinned via the documented `pinSigner` escape hatch. P4 collapses the split by putting the contracts on mainnet, where `getService` resolves live and the stronger claim language applies.
- **0G testnet RPC returns a bogus gas estimate.** A deploy silently produced zero receipts because forge estimated 0.000000015 gwei while the node requires a 2 gwei minimum tip. Always deploy with `--with-gas-price 4000000000`. Worth remembering for P4: a "successful" script run that writes a broadcast file is not proof the code is on chain, so check `eth_getCode`.
- **P2 complete: contracts green locally.** `contracts/` on Foundry, Solidity 0.8.28. 63 tests, all expected values imported from the P1 fixtures rather than restated. Solidity's rebuilt commit bytes and its on-chain `sha256` both match the reference model exactly, which is the cross-language agreement the whole fixture discipline exists to prove.
- **A failed reveal must not burn the slot.** The first implementation marked a slot invalid when a reveal failed verification. Two things were wrong with that. The state write was rolled back by the revert anyway, and more seriously, reveal is permissionless by design, so burning on failure would let anyone destroy an honest agent's completeness by spamming garbage reveals. Now a failed reveal reverts and changes nothing, and `invalid` is derived at finalize as committed-minus-revealed, after a `REVEAL_GRACE` of one day. A slot is invalid only if nobody could open its commitment in time.
- **`Entry` no longer duplicates `Commit`.** `reqSha`, `respSha` and `provider` are already stored at commit time under the same key, so persisting them again cost four extra SSTOREs per reveal. Storage is now a slim `StoredEntry` and `entryOf` joins the two for callers. Combined with a word-at-a-time memcmp, reveal dropped from 386,412 to 235,827 gas, back inside the PRD's stated budget. The hand-written assembly is fuzzed against a naive byte-wise implementation, since it is the security property on the reveal path.
- **P1 complete: `packages/reference` is the executable spec.** Pure TypeScript, zero chain deps (`@noble/hashes` + `@noble/curves` only, deliberately no ethers/viem so the reference can never inherit behaviour from a client library). 87 tests green, typecheck clean, fixtures deterministic. Property tests assert slot-resolution totality (I13) and escrow conservation (I5) rather than spot-checking them.
- **The commit line uses `slot:<k>`, not `nonce:<n>`.** In v1 the nonce carried both ordering and replay protection. In v2 the slot index does both, since slots are fixed by the schedule and each `(agent, epoch, slot)` accepts one commit. Keeping both would be redundant and would let them disagree. Consequence: `web/` still encodes `nonce:` across 12 files and is now the drifted copy. Tracked in PRD v2 §16.0; the frontend should import the reference package rather than maintain a parallel implementation.
- **Reveal is permissionless, and a failed reveal burns the slot.** Anyone holding the plaintext can reveal, so an owner cannot bury a losing call by sitting on it. A reveal that fails verification marks the slot `invalid` rather than leaving it retryable, so a bad reveal is not a free second attempt.
- **P0.2 / P0.3 executed green on 0G mainnet.** The seam spike passed every hard check with zero advisories: no broker mutation of our canonical `reqBody`, recovered signer equals `getService(provider).teeSignerAddress`, and the live parse path matched at `commitOffset` 95 with the compact `"content":"` anchor. Working provider `0x7DCFe6…e87D` (`glm-5.2`), TEE signer `0xA46EA4FC…46B9`. This retires the project's last kill trigger and unblocks P1. Details in PRD v2 §0.6.1.
- **Pin a provider set, not a provider.** `openai/gpt-5.4-mini` returns a deterministic 502 `zktls_error` despite a 1.48 OG funded sub-account, so provider health is a live variable. `EpochSpec.providerSetHash` carries the pinned set and the runtime fails over inside the commit deadline.
- **`finish_reason != "stop"` is a slot failure, never a decision.** At `max_tokens: 256` the reasoning model glm-5.2 burned the budget on reasoning and returned one character of content, which presented exactly like a model-compliance failure. The spike now defaults to 4096 and the runtime must check the finish reason.
- **Reclaimed idle Compute funds to unblock the run.** Two idle sub-accounts with refunds already pending were retrieved back into the operator's own ledger available balance (0.1 to 5.97 OG) via `retrieveFundFromProvider`: txs `0x4897b1fd…`, `0x5149e66a…`. Funds never left the owner's control. Sub-account funding for the working provider: `0xb2e72566…`.
